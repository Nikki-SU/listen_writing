# 质性编码：功能清单与界面设计

> 用途：把“质性编码”拆成可工程化的对象与功能，并给出一个自然的界面方案。
> 范围：原产品与 DSH 插件**共用同一套交互规格**；两边实现可以不同（Python / Node），但对象、流程、界面语言保持一致。
> 前提：本文不讨论“用哪个开源工具替代 NVivo”，只讨论编码这件事本身需要什么。

---

## 一、设计原则（界面的“自然”从哪里来）

1. **阅读优先**：编码发生在阅读过程中，眼睛不应离开文本。界面主体永远是转写稿，不是表格、不是卡片墙。
2. **选择即操作**：选中文字 → 就地出现码选择器；不弹模态框、不切页面、不把稿子遮住。
3. **编码可见**：编码是文本旁的“页边批注”，不是藏在右栏属性里的一个字段；重叠编码要能看见。
4. **播放与文本一体**：每一句、每一条编码都能点一下播放对应音频；不需要另开播放器窗口。
5. **布局稳定**：打开码本/检查器/检索，不应改变阅读区宽度或让正文跳动。
6. **三个视角，而非一个堆满控件的页面**：阅读编码、码本、分析、对比是四种工作状态，左上角切换，类似现有“我的录音 / 共享任务”。
7. **键盘友好**：听录音时单手可完成“暂停 / 上一句 / 下一句 / 贴常用码 / 新建码”。
8. **AI 是建议层**：AI 只给候选码、相似片段、主题建议；必须人工确认，并记录来源与依据，不许自动改正文。

> 与 `docs/交互细节清单.md` 一致：外壳永不整页滚动；滚动只发生在阅读区、码本树、结果列表等内部面板；高度从剩余空间推导，不用魔法 `calc`。

---

## 二、信息架构

> **当前前端实施口径（2026-11）**：已接入现有 React 工作区，选中录音后顶部有「转写 / 编码 / 分析 / 对比」。编码工作区三栏严格按 `2 : 5 : 3` 分配剩余宽度（左：本项目文档；中：音频 + 转写稿；右：阅读编码 ⇄ 码本），分析页为 `3 : 2`（矩阵：主题与证据）。比例全部用 `fr` 表达，可直接复算；外部项目栏固定 260px，不参与比例。正文标记用半透明荧光底色（不用下划线，避免重叠遮挡）；句子右侧 5px 竖栏按“编码覆盖字符比例”从绿（低）到红（高）着色。详见 `API_CONTRACT.md` 的「质性编码（C 系列）」数据模型。


```text
┌──────────────────────────────────────────────────────────────────────┐
│ 左上：阅读编码 | 码本 | 分析 | 对比        右上：项目 / 文档 / 保存状态 │
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 左栏 260px     │ 中间：转写稿（阅读区）                │ 右栏 320px     │
│               │                                      │               │
│ 文档/案例树    │ ┌ 播放条（细，sticky） ─────────────┐ │ 检查器         │
│ 码本摘要       │ │ ▶ 00:12 / 45:00  1.0x  循环       │ │ ─ 选中片段     │
│ 最近使用码     │ └───────────────────────────────────┘ │ ─ 已挂的码     │
│               │                                      │ ─ memo        │
│               │ 句子行：[▶][12:34][Speaker A][正文][页边码条] │ ─ 操作        │
│               │ 句子行：...                          │               │
└───────────────┴──────────────────────────────────────┴───────────────┘
```

- **左栏**：文档/案例列表 + 当前码本的摘要（或“码本树”标签）；可折叠。
- **中间**：转写稿。每句一行，左侧是播放键、时间、speaker 标签，正文可选中；右侧留一条窄“页边编码道”，画该句上的码。
- **右栏**：上下文检查器。没有选中时显示“当前文档信息 / 最近 memo”；选中片段/编码/码时显示对应详情与操作。
- **播放条**：细长、sticky，显示当前时间、速度、循环、上一句/下一句；不占大块高度。
- **模式切换**：左上角，与现有产品一致；切模式不改变项目上下文。

## 三、四种工作状态

### 1）阅读编码（默认）

```text
┌─────────────────────────────────────────────────────────────┐
│ ▶ 00:12 / 45:00   1.0x   循环   上一句 / 下一句              │
├─────────────────────────────────────────────────────────────┤
│ [▶] 00:03  Speaker A  我们其实也知道，很多活动就是为了拍照， │
│                       嗯，但是你不去又不行，所以大家就应付一下。│
│                        ┃形式化  ┃不得不参与  ┃应付策略        │ ← 页边编码道
│ [▶] 00:22  Speaker B  你说的“应付”具体是指什么？              │
│                        ┃追问                                      │
└─────────────────────────────────────────────────────────────┘
```

- 选中文字后，在选区旁弹出**码选择器**：
  - 搜索框（输入即过滤）
  - 最近使用 / 收藏码
  - “用选中文字新建码（in vivo）”
  - 可多选，一次给片段挂多个码
  - `Enter` 新建，`Esc` 关闭
- 页边编码道：每条编码是一条彩色小条，与文本垂直对齐；重叠编码分道堆叠；点小条＝选中该编码 + 播放对应音频。
- 句子行左侧的 `[▶]` 只播这一句；点时间/正文跳转。
- `M` 给当前句/片段加 memo；`C` 打开码选择器；数字键给收藏码。

### 2）码本

```text
┌───────────────┬─────────────────────────────────────────────┐
│ 码树           │ 码详情                                       │
│ ▾ 形式化治理   │ 名称：应付策略                               │
│   ├ 拍照留痕   │ 定义：以最低成本完成参与，避免公开冲突        │
│   ├ 表格迎检   │ 纳入：走流程、拍照、填表、应付检查            │
│   └ 应付策略   │ 排除：真正认同并主动参与；单纯抱怨            │
│ ▾ 参与资格     │ 示例：P03 00:03「大家就应付一下」              │
│   ├ 不得不参与 │ 颜色：橙    状态：启用    版本：v3            │
│   └ 无力感     │ [改名] [合并到…] [停用] [查看所有片段]        │
└───────────────┴─────────────────────────────────────────────┘
```

- 码树支持拖拽调整层级、合并码、停用码；改名/合并要级联到所有编码记录。
- 码详情必须有：定义、纳入/排除标准、示例、颜色、状态、版本。
- 码本版本切换：查看历史版本、对比 diff；切到旧版本只读，避免误改。
- “查看所有片段”直接跳到检索结果，带上下文与播放。

### 3）分析

三个标签：

- **矩阵**：`code × case` 表格，单元格是该码在该案例中的片段数；点单元格 → 片段列表。
- **主题板**：候选主题卡片（主题名、定义、证据数、反例数）；拖码进主题；点主题 → 证据清单。
- **检索**：条件构建器（码、案例、speaker、时间范围、是否含反例）；结果列表带上下文与播放。

```text
主题板
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ 形式化的识别  │  │ 制度性约束    │  │ 策略性顺从    │
│ 证据 18 · 反例 2│ │ 证据 12 · 反例 1│ │ 证据 9 · 反例 0 │
└──────────────┘  └──────────────┘  └──────────────┘
```

### 4）对比（多编码者）

- 顶部切换编码者：`我 / 全部 / P02`。
- 正文下划线按编码者着色；同一片段两个人都编码 → 双色下划线。
- 右侧“分歧列表”：仅一人编码、码不同、边界不同；逐条裁决，写入裁决记录。
- 一致性面板：按码的 Cohen's κ / Krippendorff's α、一致片段数、待裁决数。
- 对比模式默认只读，裁决动作显式。

## 四、核心交互（必须顺）

1. **编码一个片段**：拖选文字 → 弹码选择器 → 选 1–N 个码 → 页边出现彩条 → 自动保存（乐观更新，失败回滚）。
2. **听录音改编码**：点句子播放 → 听到某半句 → 暂停 → 选中半句 → 贴码/改码；不离开阅读区。
3. **回放一条编码**：点页边彩条 → 播放该片段对应音频；再点一次暂停。
4. **新建 in vivo 码**：选中受访者原话 → “用这句话建码” → 码名自动填入，可编辑定义。
5. **合并码**：码本里把一个码拖到另一个码 → 确认 → 所有编码记录级联迁移，留 audit。
6. **写 memo**：选中片段/码 → `M` → 右栏内联 Markdown 编辑 → 自动保存；memo 可挂多个对象。
7. **找证据**：点主题/码 → 右栏或分析页列出全部片段 → 点片段回到阅读区并播放。
8. **对比裁决**：对比模式点分歧 → 选择保留谁的编码/合并边界 → 记录裁决人、时间、理由。

## 五、功能清单（按优先级）

### P0：能编码

- 字符级 span 选择（句内 + 跨句）
- 码选择器：搜索、最近、收藏、in-vivo 新建
- 一个片段多码、码可重叠
- 页边编码道 + 点彩条播放
- 码列表（扁平）+ 定义 + 颜色
- 片段/句子 memo（内联）
- 按码检索片段 + 上下文 + 播放
- CSV / JSON 导出；基础 audit（谁、何时、改了什么）

### P1：能分析

- 码树与码本版本；改名/合并级联
- 主题 + 证据清单 + 反例计数
- code × case 矩阵、码频次、共现
- 检索条件构建器
- 转写稿改版后的编码迁移（重锚定 + 待确认）
- REFI-QDA 导出（`.QDPX` / `project.QDE`）

### P2：团队与 AI

- 多编码者任务分配、独立编码、对比、裁决
- Cohen's κ / Krippendorff's α
- AI 辅助：候选码、相似片段、主题建议；`source=ai`、置信度、依据片段；必须人工确认
- 主题关系图、审计日志导出、协作

## 六、数据模型（概念层）

```text
documents(id, recording_id, title, ...)
sentences(id, document_id, index, text, start_ms, end_ms, speaker)

codes(id, codebook_version, parent_id, name, definition,
      inclusion, exclusion, color, status)
codebook_versions(id, parent, diff, snapshot)

codings(id, document_id, sentence_ids, char_start, char_end, quote,
        code_id, coder_id, source, confidence, created_at, status)

memos(id, target_type, target_id, author, text, tags, created_at)
themes(id, name, definition, parent_id)
theme_codes(theme_id, code_id)

assignments(document_id, coder_id, scope)
audit_events(id, actor, action, target_type, target_id, before, after, ts)
```

工程含义：

- `codings` 是核心表：片段 × 码 × 人 × 来源。
- `sentence_ids` 允许一条编码跨多句；`char_start/char_end` 是句内偏移（或首句偏移 + 跨句长度，按实现定）。
- 文本被编辑/重切分时，用 `quote + offset` 重锚定；失败标记 `needs_review`。
- 脱敏在展示层叠加，不改变 `codings` 的原文锚点。
- 码本版本与转写版本分离；导出时带上是哪个版本。

## 七、待确认

1. 编码道是放在句子右侧（页边），还是正文下方独立一行？——推荐页边，阅读不中断。
2. 跨句编码在页边如何画？——推荐“起始句一条、后续句细线延伸”，或折叠为一个括号标记。
3. 对比模式是并排两份稿，还是同一份稿叠加双色？——推荐叠加，省空间、便于看边界差异。
4. 主题板是自由画布还是卡片列？——推荐先卡片列（可排序/拖拽），后期再加关系线。
5. 音频是否要做波形？——P0 不做；先把“点句/点编码精确播放”做准。
