# PRD v1.0

## 1. 产品定义

本地优先、开箱即用的质性研究录音转写与协作工作台。自带可运行的本地 ASR 与本地 LLM，随软件分发；界面通过 Chromium 系浏览器访问，模型、数据和推理留在本机或局域网，不出外网。

## 2. 顶层原则

1. **傻瓜式**：首次打开只做必要权限请求，除此之外无学习成本。
2. **数据不出本地/局域网**：伦理硬线。
3. **自带模型、开箱即用**：默认模型已配置好。**模型选择在设置中随时可用**，提供三种 ASR 与三种 LLM 选项，各自标注适用场景、最低配置和预期速度。微调模型才属于高级选项。
4. **功能不妥协**：答应了做的功能必须做到，不以"简化版"为由降级；没做的功能不算妥协。
5. **实现方式服务于功能**：技术选型不是 PRD 中心。

## 3. 目标用户

质性研究者、课题组研究助理/管理员、只读访客（本科生、审查者）。

## 4. 部署形态

- Windows + Ubuntu LTS；最低配置 **16GB RAM + 512GB 存储**，普通办公本，无独显要求。
- 本地后端承载模型、推理、文件读写、局域网协作，是产品本体。
- 前端为浏览器界面，主通道部署 GitHub Pages；后端内嵌前端副本，Pages 不可达时回退本地。
- 轻量启动器负责拉起后端并打开浏览器。
- Chromium 系浏览器即可，不要求兼容所有浏览器。

## 5. 身份与设备

- 无登录界面、无密码。以 **昵称 + 设备码** 标识一个人。
- 设备码可设置；昵称与设备码一致的多台设备视为同一人的设备，之间共享全部信息，实现多设备同步。
- 配对码用于局域网协作，类似面对面建群；进群后按昵称识别身份并分配权限。
- 权限绑定在人（昵称身份）上；同一人的设备通过设备码关联，共享同一权限。
- 无中心服务器；P2P 特性决定只能在局域网内使用。

## 6. 项目、录音与版本

- **项目**：研究容器，回答"你在做什么事"；项目下可含多个录音，对应多个受访者/多次访谈；为后续编码功能预留复用基础。
- **群组**：协作容器，回答"你和谁一起做"；与项目无直接关系。
- **版本号**：`阶段.阶段内序号`。阶段内独立计数，阶段升级时序号重置。首版为 `0.1`；进入阶段 1 后为 `1.1`。
- 阶段定义：**0 = 初始转写稿；1 = 文字润色稿；2 = 脱敏稿**；阶段可扩展。
- 任何一次改动（含合并）提交一个 commit，产生新版本号。
- 版本号的数学原则：任意两次版本号之间必须能对应改了什么，并能复刻。
- 文字润色与脱敏是两类不同操作，分属不同阶段，产物为不同版本。

## 7. 转写

- 音频输入格式：**WAV、MP3、M4A、WMA**。
- 本地转写；多人录音 MVP 必须；不要求中英混说。
- **发言人区分**：自动聚类输出 Speaker 1/2/…，**允许人工标注身份**（如"访员A""被访者B"）；支持人工合并、拆分、重命名发言人。
- 方言与错误读音兼容取决于所选 ASR 模型能力；产品不训练模型。
- ASR 模型三选项（设置中随时可切换，各自标注最低配置与预期速度）：

| 选项 | 定位 | 16GB 办公本可行性 |
|---|---|---|
| Whisper（small/medium） | 通用兜底，生态成熟 | 可跑，约实时 1.5–2 倍 |
| Qwen3-ASR-0.6B | 中文方言平衡，22 种中文方言 | 可跑，约 2.5GB |
| SenseVoice Small | 轻量快速，中文/粤语准确率好 | 极轻，峰值 <800MB |

## 8. 逐句校对

- 点击句子精确跳转对应音频位置。
- 可精确手动修改单句。
- 修改留痕，可追溯。

## 9. AI 功能（LLM）

- AI 是**可调用功能**，不限制用户在什么时候使用它。
- **语义纠错**用于润色阶段（0→1）：语义提示疑似转写错误，以修订模式呈现，可接受/拒绝/自己改；不自动改正文。
- **脱敏标记**用于脱敏阶段（1→2）：语义标记需脱敏位置，不同颜色对应不同类型。
- ASR 只负责转写；语义纠错与脱敏标记均由 LLM 承担。
- LLM 模型三选项（设置中随时可切换）：

| 选项 | 定位 | 16GB 办公本可行性 |
|---|---|---|
| Qwen3-1.7B Q4 | 最低配置默认回退档 | 可跑，速度较快 |
| Qwen3-4B Q4（默认） | 中间平衡档 | 可跑，精度与速度折中 |
| Qwen2.5-7B Q4 | 精度优先档 | 可跑，速度较慢（1–5 tok/s） |

- 模型选择只告知最低配置要求，用简洁语言；不替用户判断硬件、不弹大段警告。

## 10. 脱敏

- 类别可自定义：可新增、删除、按次启用或停用已有类别。
- 产品提供一组**建议起点标签**（人名、地点/机构、日期/联系方式、职业/身份等），它们是可编辑的预设标签，不是不可变清单；研究者可按课题保存自己的类别模板。
- 脱敏是替换；占位符**可配置**，默认 `[类别名]`。
- 导出物不携带敏感信息。

## 11. 导出

- 格式：**Markdown + JSON**。MD 便于 diff、审阅、送审；JSON 保留发言人、时间戳、句子级映射、脱敏标记等结构。不做 DOCX。
- 默认导出当前最新版本；**可选历史版本导出**。
- 脱敏后的导出物不得包含原始敏感信息。

## 12. 协作

**12.1 群组与配对码**
- 配对码即群组，类似面对面建群；可长期或临时。
- 用法是微信群 + 朋友圈的混合：材料可以发到群里；也可以控制谁能看、谁能动。
- 管理员及以上可灌材料，灌入的是**当前版本**；读写只能看材料和提交类 PR 修改；只读只能看。

**12.2 节点与版本**
- 每个研究者是独立节点，各有本地数据和版本；参考 git 分布式提交与合并。
- 读写改自己本地副本，提交合并请求，群主/管理员逐个决定是否合并；群主/管理员可批量合并（全选、合并自己提交的、合并全部待处理），冲突句自动跳过留给人工判断。
- 群主/管理员自己修改正文时可直接合并落库，不必先提提案再自己批。
- 两个节点同时改同一句，不同位置可正常合并；冲突时人工判断解决。

**12.3 群组两种模式**（群主设定）
- 无副本：群主是权威节点，群主不在线别人不能用；合并为中心化审批。
- 有副本：成员本地可有副本，任一节点在线群组即可用；需要分布式版本控制与冲突合并。

**12.4 权限**
- 默认四级模板：群主、管理员、读写、只读；每级能力可自定义，非硬编码。
- 群主可任命所有权限；管理员可任命下级，邀请其他管理员需群主通过。
- 授权支持长期角色模板与单次/单材料授权。
- 只读本地无副本，只能看；不可下载音频；用途是本科生参观与审查者查看。

**12.5 只读播放音频**
- 只读申请播放，批准后播放**整段录音**。
- 批准模式三种：**阅后即焚**（听一次即失效）、**永久可听**、**限时有效**（如 7 天过期）。
- 由管理员或群主批准；他们本人有审批权，点播放即直接放行并留痕，不必自己批自己。

## 13. 审查模式

- MVP 低优先级，保留原则，细节迭代。
- 审查是群组内叠加在只读之上的模式；审查者通过配对码加入群组，权限高于普通只读。
- 不向审查者交付可带走的材料；技术上采取禁止下载、禁止复制、页面水印含审查者标识与时间、访问留痕等措施，提高拿走成本并使其可追溯。
- 审查可见范围从版本 2 之后开始；**版本 2 之前的 commit 历史也截断**，因为历史中可能包含内容。

## 14. 编码（预留，暂不实现）

- 项目层之下、与录音/版本并列的独立功能区域。
- MVP 不包含编码功能；现阶段用 NVivo 承担。
- 预留边界：编码是分析层，叠加在文字稿版本之上，不改变 0/1/2 版本体系；挂在项目下随项目复用；数据结构待定，本 PRD 不做规定。
- 不先做简版，避免数据结构未想清楚就绑死底层版本数据。

## 15. 非功能需求

- **隐私合规**：数据不出局域网；前端静态代码不上传数据；音频永不外送。
- **易用性**：傻瓜式；默认合理；内部概念不暴露。
- **可追溯**：版本、提交、合并、访问与播放审批留痕。
- **稳定性**：长音频、多人录音、任务失败可恢复。
- **跨平台**：Windows + Ubuntu LTS；16GB+512GB 办公本为最低配置。

## 16. MVP 范围

**包含**：身份与设备码、项目/录音/版本管理、录音导入、本地转写、发言人聚类与人工标注、逐句校对与音频跳转、AI 修订模式、脱敏标记与替换导出、MD/JSON 导出、配对码群组、默认四级可自定义权限、只读审批播放（三种批准模式）、轻量启动器与浏览器界面。

**不包含**：自研 ASR/LLM、编码功能（预留区）、送审通道细节（低优先级迭代）、通用会议记录、全浏览器兼容、云端 SaaS、中英混说硬指标、DOCX 导出。
